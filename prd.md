# PRD: Конструктор тестов по геометрии для oilau.kz

| | |
|---|---|
| **Продукт** | Конструктор тестов по геометрии из видеоуроков |
| **Платформа-получатель** | oilau.kz |
| **Пользователи** | Менеджеры по обучению (интеграция контента) |
| **Предмет и охват** | Геометрия, 7–11 классы |
| **Статус** | MVP опубликован: https://claude.ai/artifact/MKQWXNM4KGjceNw8GMxJ8o |
| **Дата** | 03.11.2026 |

---

## 1. Цель и ценность

На платформе oilau.kz есть видеоуроки по геометрии с текстовыми конспектами, но нет тестов к ним. Тесты по геометрии сложно делать вручную: в вопросах и вариантах ответа нужны точные чертежи, а их подготовка занимает у методиста больше времени, чем сам текст.

Инструмент превращает один урок в готовый набор тестов с чертежами и файлами для загрузки на платформу. Это позволяет внедрить геометрию в oilau.kz в разумные сроки и без найма иллюстраторов.

**Ключевой результат:** менеджер за один сеанс (≈ 10 минут работы и 3–6 минут ожидания) получает 5 проверенных тестов по уроку в форматах, готовых к интеграции.

## 2. Пользователи и сценарий

**Основной пользователь — менеджер по обучению.** Он интегрирует контент в платформу. Он не обязательно методист-геометр и не дизайнер, поэтому инструмент должен сам обеспечивать предметную корректность и качество рисунков, а от менеджера требовать только проверки и мелких правок.

**Основной сценарий:**
1. Менеджер открывает инструмент по ссылке в claude.ai.
2. Выбирает класс и язык вопросов.
3. Вставляет конспект или расшифровку видео, загружает скрины доски учителя.
4. Запускает генерацию и следит за прогрессом.
5. Просматривает 25 вопросов, исправляет помеченные.
6. Скачивает Word, TXT и архив с рисунками и загружает их на платформу.

## 3. Объём (scope)

### Входит в MVP
- Ввод урока: конспект, расшифровка видео, скрины доски, ссылка на видео.
- Генерация 25 вопросов и компоновка 5 тестов.
- Построение точных чертежей в вопросах и в вариантах ответа.
- Автоматическая проверка ответов независимым проходом.
- Просмотр, редактирование, точечное исправление и замена вопросов.
- Экспорт: Word, TXT в формате платформы, PNG-рисунки.
- Языки: казахский, русский, любой другой по названию.

### Не входит в MVP
- Автоматическое чтение видео и субтитров с YouTube (см. раздел 9).
- Прямая загрузка на oilau.kz через API.
- Совместная работа нескольких менеджеров над одним набором.
- Хранение истории наборов на сервере.

## 4. Функциональные требования

### 4.1. Ввод урока

| ID | Требование |
|---|---|
| IN-1 | Выбор класса: 7, 8, 9, 10, 11. |
| IN-2 | Выбор языка вопросов: Қазақша (по умолчанию), Русский, Другой (поле для названия языка). |
| IN-3 | Поле «Тема урока» — необязательное; если пусто, тема определяется по конспекту. |
| IN-4 | Поле «Ссылка на видео» — необязательное, выводится в шапку Word-документа. |
| IN-5 | Поле конспекта / расшифровки с загрузкой файлов .txt, .md, .docx. |
| IN-6 | Подсказка, как получить расшифровку видео: YouTube → «…» → «Показать расшифровку». |
| IN-7 | Загрузка скринов доски учителя: перетаскиванием, вставкой из буфера (Ctrl+V / ⌘V), выбором файлов. Миниатюры с удалением. Лимит количества — по ограничениям claude.ai, показывается под полем. |
| IN-8 | Скрины уменьшаются в браузере до 2000 px по большей стороне. |
| IN-9 | Для запуска достаточно конспекта (от 300 символов) или хотя бы одного скрина. |

### 4.2. Генерация

**Состав набора:**

| Уровень | Кол-во | Характер |
|---|---|---|
| Лёгкий | 5 | Определение или свойство, одна формула, 1 шаг |
| Средний | 10 | 2–3 шага, вычисление по чертежу, комбинация двух свойств |
| Сложный | 5 | Несколько шагов, дополнительное построение или неочевидное свойство |
| Суперсложный | 5 | Олимпиадного типа в пределах программы класса, однозначный ответ |

**Компоновка:** 5 тестов по 5 вопросов, в каждом 1 лёгкий + 2 средних + 1 сложный + 1 суперсложный.

| ID | Требование |
|---|---|
| GEN-1 | Шаг 1 — разбор урока: тема, краткое содержание, ключевые факты, план 25 вопросов (идея, тип чертежа, что изображено). |
| GEN-2 | Не менее 70% вопросов содержат рисунок; целевое значение — 19 из 25 (76%). Если план даёт меньше, инструмент сам переводит вопросы без чертежа в вопросы с чертежом. |
| GEN-3 | Типы чертежей: в условии (не менее 16), в вариантах ответа — «На каком рисунке…» (2–3), без чертежа (не более 6). |
| GEN-4 | Если загружены скрины доски, на шаге 1 Claude описывает каждый чертёж (фигура, обозначения, подписи, числа). Описания передаются во все последующие шаги. В вопросах сохраняются фигуры и обозначения урока; часть вопросов строится по чертежам с доски с другими числами. |
| GEN-5 | Шаг 2 — генерация каждого теста отдельным запросом, по 2 теста параллельно. |
| GEN-6 | У каждого вопроса ровно 5 вариантов и ровно 1 верный. Неверные варианты — типичные ошибки учеников, в одном формате и единицах. Запрещены «все ответы верны» и «нет верного ответа». |
| GEN-7 | Условие самодостаточно: все данные есть в тексте или в подписях чертежа. |
| GEN-8 | Числа подбираются так, чтобы ответ был «красивым». |
| GEN-9 | Формулы — Unicode (° √ π ∠ △ ⊥ ∥), степени `^2^`, индексы `~1~`, как в образце платформы. Без LaTeX и Markdown. |
| GEN-10 | Позиции верных ответов сбалансированы по набору: каждая буква A–E верна ровно 5 раз из 25. |
| GEN-11 | Прогресс по шагам с таймером; кнопка «Остановить»; повтор отдельного шага при ошибке без перезапуска всего набора. |

### 4.3. Чертежи

Принцип: Claude не рисует картинку, а описывает построение в формате JSON. Инструмент сам вычисляет координаты и рисует чертёж. Это гарантирует, что чертёж соответствует данным задачи: медиана делит сторону пополам, угол 50° выглядит как 50°.

| ID | Требование |
|---|---|
| FIG-1 | Точки задаются координатами или вычисляются: середина, основание перпендикуляра, точка на отрезке в заданном отношении, пересечение прямых, полярные координаты, достройка параллелограмма, симметрия, центры вписанной и описанной окружностей, центроид. |
| FIG-2 | Элементы: многоугольник с заливкой, отрезок, прямая, луч, вектор, окружность, вписанная и описанная окружности, дуга, обозначение угла (1–3 дуги), прямой угол, штрихи равенства, точка, текстовая подпись. |
| FIG-3 | Координатная плоскость с сеткой и графики функций (собственный безопасный парсер формул). |
| FIG-4 | Стереометрия (10–11 классы): косоугольная проекция для многогранников, фронтальная — для тел вращения; горизонтальные окружности оснований и шар; невидимые линии штрихом. |
| FIG-5 | Автомасштаб с сохранением пропорций; автоматическое размещение подписей точек вне линий и дуг; подписи отрезков снаружи фигуры; сдвиг подписи, если она сталкивается с точкой. |
| FIG-6 | Стиль: белый фон, чёрные линии, синий акцент для искомого и важного, серый для вспомогательного, курсивные подписи точек с индексами (A₁). |
| FIG-7 | Чертёж не подсказывает ответ: искомое обозначается «?» или «x». |
| FIG-8 | Ошибка построения показывается на месте рисунка с подсказкой, как исправить. |

### 4.4. Проверка качества

| ID | Требование |
|---|---|
| QA-1 | После генерации каждого теста — независимый проход: Claude заново решает вопросы, не видя отмеченного ответа. |
| QA-2 | Проверяется: совпадение ответа, единственность верного варианта, соответствие чертежа условию, достаточность данных, язык и терминология. |
| QA-3 | Статусы вопроса: «ответ подтверждён», «требует проверки» (с текстом замечания), «проверяется», «не проверен». |
| QA-4 | Фильтр «Проверить» показывает только вопросы с замечаниями; в нижней панели — счётчик таких вопросов. |
| QA-5 | После исправления или замены вопрос проверяется повторно автоматически. |

### 4.5. Просмотр и редактирование

| ID | Требование |
|---|---|
| ED-1 | Список вопросов, сгруппированный по тестам; фильтр: все, тест 1–5, требующие проверки. |
| ED-2 | Карточка вопроса: номер, уровень, статус проверки, текст, чертёж, варианты, решение (раскрывается). |
| ED-3 | Правка текста вопроса и вариантов прямо в карточке. |
| ED-4 | Смена верного варианта нажатием на букву. |
| ED-5 | «Исправить по замечанию» — одним нажатием по тексту замечания проверяющего. |
| ED-6 | «Исправить с Claude» — замечание своими словами (например: «подпиши угол B = 50°»). |
| ED-7 | «Заменить вопрос» — новый вопрос того же уровня и типа чертежа, без повторов с остальными. |
| ED-8 | «Код рисунка» — ручная правка JSON чертежа с проверкой перед применением. |
| ED-9 | Набор сохраняется в браузере и восстанавливается после перезагрузки. Скрины доски не сохраняются, их текстовые описания сохраняются. |

### 4.6. Экспорт

Три основных файла плюс общий архив.

**1. Word (.docx)**
- Шапка: тема, предмет, класс, число вопросов и тестов, ссылка на видео.
- Каждый тест с новой страницы; вопросы по порядку с номером и уровнем.
- Рисунок к условию — под текстом вопроса.
- Варианты A–E; верный выделен зелёным и отмечен ✓.
- Варианты-чертежи — таблицей 3 + 2, строки не разрываются между страницами.
- Краткое решение (отключается в настройках).
- Ключ ответов в конце документа.
- Формат A4, поля 2 см, шрифт Arial. Подписи на языке вопросов.

**2. TXT в формате платформы** (по образцу `questions__8_.txt`)
- Кодировка UTF-8, переносы строк CRLF.
- Строка вопроса: `N. Текст вопроса`, сквозная нумерация 1–25 в порядке тестов.
- Варианты: `(!)` — верный, `(?)` — остальные.
- Пустая строка между вопросами.
- Степени и индексы: `^…^` и `~…~`.

```
3. Суреттегі үшбұрыштың ауданын табыңыз. [img:q03.png]
(?) 10 см^2^
(!) 20 см^2^
(?) 15 см^2^
(?) 12 см^2^
(?) 8 см^2^

```

- Метка рисунка добавляется в конец строки вопроса или варианта. Шаблон настраивается (по умолчанию `[img:{file}]`), метку можно отключить.

**3. Рисунки (ZIP, папка `images`)**
- PNG, белый фон: рисунки к условию — 1600 px по ширине, рисунки вариантов — 960 px.
- Имена: `q03.png` — рисунок к условию вопроса 3; `q07_a.png` … `q07_e.png` — рисунки вариантов вопроса 7. Номер совпадает с номером вопроса в TXT.

**4. «Всё одним архивом»** — Word, TXT и папка `images` в одном ZIP.

## 6. Техническая архитектура

- **Одна HTML-страница**, опубликованная как Artifact в claude.ai. Внешние библиотеки: JSZip (архивы, чтение .docx); шрифт Inter.
- **Обращение к Claude** — через возможность страницы `sample` (модель уровня `complex`, с передачей изображений). Запросы идут от аккаунта менеджера и расходуют его лимит; при первом запуске claude.ai запрашивает разрешение.
- **Скачивание файлов** — через возможность `downloads` с подтверждением пользователя.
- **Конвейер:** разбор урока → генерация тестов (2 параллельно) → проверка каждого теста.
- **Чертёж:** JSON-описание → вычисление точек → единый список примитивов → два вывода: SVG для экрана и Canvas для PNG.
- **Word** собирается в браузере вручную из OOXML без сторонних библиотек.
- **Хранение:** localStorage в браузере менеджера; сервера нет.

## 8. Риски

| Риск | Смягчение |
|---|---|
| Ошибка в ответе, особенно в суперсложных вопросах | Независимая проверка, статус «требует проверки», обязательный просмотр менеджером перед загрузкой |
| Чертёж не соответствует условию | Построение через вычисляемые точки; проверка соответствия на проходе QA; ручная правка кода рисунка |
| Неточная терминология на казахском | Заданный словарь терминов; проверка языка на проходе QA; рецензия методиста на первых уроках |
| Скудный конспект — слабые вопросы | Скрины доски как второй источник; поле темы |
| Лимиты аккаунта Claude у менеджера | Сообщение о лимите, повтор позже, повтор отдельного шага |
| Формат меток рисунков не совпадает с импортом платформы | Настраиваемый шаблон метки (см. открытые вопросы) |

## 9. Ограничения

- **YouTube.** Страница в claude.ai не может открыть видео или скачать субтитры. Решение: менеджер копирует расшифровку видео и добавляет стоп-кадры доски.
- **Скрины** не сохраняются после перезагрузки страницы (сохраняются их описания).
- **Работа только внутри claude.ai:** вне его генерация и скачивание недоступны.

## 10. Открытые вопросы

1. **Как oilau.kz связывает вопрос с рисунком при импорте TXT?** В образце нет вопросов с картинками. Сейчас используется метка `[img:q03.png]`; нужен формат, который реально принимает платформа.
2. Нужен ли отдельный TXT на каждый тест или достаточно одного файла на 25 вопросов?
3. Нужны ли решения в Word, который увидят учителя, или только во внутренней версии?
4. Какие ещё языки планируются после казахского и русского и есть ли для них словари терминов?
5. Кто проводит методическую рецензию первых наборов и по каким критериям?

## 11. Дальнейшее развитие

- Прямая загрузка набора на oilau.kz через API платформы.
- Автоматическое получение расшифровки и ключевых кадров видео вне браузера.
- Проверка чертежа по изображению: Claude смотрит на итоговый PNG, а не только на JSON.
- Словари терминов для новых языков.
- Расширение на другие предметы с рисунками: физика, алгебра (графики), черчение.
- Банк вопросов: повторное использование и перемешивание тестов между уроками.
